How a run flows

browser  ──POST /run──▶  FastAPI
                          │
                          ├─▶ Kafka  jobs.requested   (durable, partitioned by app)
                          │            │
                          │            ▼
                          │        worker  ──▶ Ollama (8 requests in flight)
                          │            │
                          │            ├─▶ Redis  generation cache  (shared by all ten apps)
                          │            ├─▶ Redis  job state + pub/sub
                          │            └─▶ Kafka  jobs.completed    (replayable result log)
                          ▼
browser  ◀──SSE──────  Redis pub/sub

If Kafka is unreachable the job runs in-process instead. The run still completes and the page still streams, but it is not replayable — the badge on the run page says which path it took.
